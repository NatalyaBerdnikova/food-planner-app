# Product Vision

## Название

**Food Planner** — iOS-приложение для планирования питания, рецептов и покупок с учётом персональных норм КБЖУ и микронутриентов.

Bundle / App Group: `group.com.natalya-berdnikova.food-planner`  
URL scheme: `foodplanner://` (импорт рецептов, вкладки, open `.foodplan`)

## Проблема

Люди сохраняют рецепты из соцсетей и блогов, но теряют их в ленте. Планирование недели, список покупок и контроль калорий/БЖУ живут в разных приложениях. Нет единого места, где:

1. рецепт из Instagram превращается в структурированную карточку с ингредиентами из каталога;
2. рецепты раскладываются по дням и приёмам пищи (вручную или автогенерацией под цели);
3. автоматически собирается список покупок;
4. видно прогресс к дневным целям питания;
5. план можно передать тренеру / себе на другое устройство файлом.

## Ценностное предложение

> Импортируй рецепты из привычных источников → собери (или сгенерируй) неделю → купи продукты → готовь с пониманием макросов и микронутриентов.

Ключевые дифференциаторы:

- **импорт из Instagram** (Share Extension + LLM-парсинг) с матчингом к локальному каталогу (~490 продуктов);
- **недельный planner** с автогенерацией под дневные цели КБЖУ;
- **обмен планом** через `.foodplan` (средние КБЖУ для сверки с тренером).

## Для кого

| Персона | Потребность |
| --- | --- |
| **Планировщик** | Хочет заранее разложить завтраки/обеды/ужины на неделю и не думать в магазине |
| **Собиратель рецептов** | Черпает идеи из Instagram / TikTok / блогов и хочет сохранить их «как рецепт», а не скриншот |
| **Осознанный едок** | Следит за калориями, белком и отдельными микронутриентами (до 5 фокусных) |
| **С тренером** | Делится недельным планом файлом с карточкой средних КБЖУ |

## Не цель продукта

- Полноценная соцсеть (лента комментариев, фолловинг).
- Клинический диетологический сервис / медконсультации.
- Облачный sync между устройствами как обязательное ядро (сейчас локальный SwiftData + файловый обмен планом).

Лёгкий social proof (community likes) допустим как UX-сигнал, не как социальная платформа. См. [06-design-system.md](06-design-system.md).

## Продуктовые принципы

1. **Рецепт — единица ценности.** Каталог + пользовательские + импортированные живут в одной библиотеке.
2. **План недели — единица организации.** День → слоты приёмов пищи → рецепт; план можно сгенерировать, очистить, экспортировать.
3. **Питание считается из ингредиентов.** КБЖУ и микро — производные от каталога продуктов, не «магические» поля без связи.
4. **Photo-first UI.** Еда визуально важнее chrome (референс Kitchen Stories).
5. **Локально-first.** Данные на устройстве; сеть нужна для импорта, LLM и подписки.
6. **Вовлечение без давления.** Trial-напоминания ведут к плану/покупкам, не к «оформите подписку»; отзыв — только после позитивного сигнала и не в день первого открытия.

## Успех (качественные критерии)

- Пользователь за один сеанс: импортировал рецепт → добавил в план → увидел обновлённый shopping list.
- Дневные цели КБЖУ отражают реальный план на сегодня.
- Генерация недели даёт съедобный план в зоне целей без ручного перебора каталога.
- Пустые состояния ведут к одному понятному действию (добавить рецепт / импорт / сгенерировать / заполнить слот).

## Платформа

- **iOS / iPadOS** (SwiftUI + SwiftData); layout по size class (readable columns, adaptive grids, form sheets).
- Share Extension (без compose): URL → App Group + deep link → импорт в main app.
- Локализация: система / English / Русский (каталог в LLM-промпте — на языке UI).
- Монетизация: подписка Pro через Adapty (`premium`), hard paywall до доступа; mocks только для Previews (`AppVars.useSubscriptionMocks`); Debug/TestFlight — `allowsContinueWithoutSubscription`.
